## 待定（先不做，等后续决定）

- [ ] **雨天备选上地图**
  - 现状：`alt` 只写进文字行程与 `plan.html`；地图与分享图不显示备选点。
  - 顾虑：备选点用虚线/灰标会与主路线视觉打架，`map_poster` / `map_day_XX` 版面可能变乱；标签避让也要重算。
  - 若要做的方案：`generate_travel.py` 给备用 stop 打 `_alt=true` → 灰色虚线 marker + 连回主点；分享图默认**不渲染**备选，加开关 `--types mapday,alt` 才出。
  - 决定时间：等 `plan.html` 上线、看真实用户是否真的会在手机上对照备选点。

- [ ] **景点位置示意小图（`--types place`）**
  - 参考对象：travel-planner 手工在地图 App 截「位置示意小图」。
  - 我们的做法：复用 `__filterDay__` + 单点 `setView(zoom 15)`，出 800×800 方形小图插进 `plan.html` 的调研章节。
  - 顾虑：与「路线图三层」信息重复；先看 `plan.html` 是否真需要每景点一张图。

- [ ] **中间长腿也切分（多块图 / 分幅）**
  - 背景：2026-11 西安→丽江 的 `route_map.png` 被两条 1,170km 的飞行腿把包围盒撑到 1500km，
    区内动线（110km）挤成一坨。v1.3.1 已处理**首腿/末腿**（自动移出范围 + 灰虚线 + 角标 + 看全程切换）。
  - 未处理：**中间腿**。例如「北京→成都（飞）→ 川西自驾 → 成都→北京（飞）」，或「昆明→版纳」这种中途转场；
    如果也切，地图会变成两块不相连的簇（A 簇、B 簇），单幅图讲不清。
  - 若要做的方案：按 >400km 的腿把站点切成连通分量 → 选站点最多的簇作主图，其余各簇出一张副图
    （`route_map_2.png` 或 `map_poster` 分页）；或主图 + 角标里标「另有 B 段见附图」。
  - 顾虑：交付物变多、分享图排版要重做、自检口径要改（每幅图各自校验标记数）。
  - 决定时间：等出现真实的多段行程需求再排，别为假设场景提前加复杂度。

- [ ] **多城市/出境行程的汇率与签证提示**
