# 坐标来源与坐标系规范

`itinerary.json` 里**一律存 WGS-84**（与 OSM/GPS 一致）。但取坐标的来源不同，坐标系也不同，直接混用会让标记偏 300~600m（云南实测 341~351m）。

## 一、来源 → 坐标系对照

| 来源 | 坐标系 | 能否直接用 |
|---|---|---|
| Photon（脚本首选，`photon.komoot.io`） | WGS-84（OSM 数据） | ✅ 可直接填 |
| Nominatim / OSM 节点 / Wikipedia / Wikidata | WGS-84 | ✅ 可直接填 |
| 腾讯地图、高德地图、政府公示中的经纬度 | **GCJ-02** | ❌ 必须换算 |
| 百度地图 | **BD-09**（在 GCJ-02 基础上再偏移） | ❌ 必须先转 GCJ-02 再转 WGS-84 |
| 手机 GPS 打点、Google Maps | WGS-84 | ✅ 可直接填 |

换算命令（本专家包内）：

```bash
python3 bin/coord_convert.py gcj2wgs 22.602054 101.097496   # -> 22.604820 101.095948（偏移 347 m）
python3 bin/coord_convert.py wgs2gcj 22.604820 101.095948
python3 bin/coord_convert.py gcj2wgs --json 22.602054 101.097496
```

**两条防线**（任一即可，建议都用）：
1. 拿到 GCJ-02 坐标后先跑 `gcj2wgs` 换算，把结果写进 `itinerary.json`；
2. 或在 stop 上标 `"coord_source": "gcj02"`，交给 `generate_travel.py` 在出图前自动换算（脚本会把它改写成 `wgs84`）。

> 脚本按行程范围自动选底图：中国大陆用高德（内部把 WGS-84 转 GCJ-02 贴合路网），境外用 OSM。**不要手工做 GCJ 偏移**，否则会被转两次。

## 二、地理编码为什么常常失败（实测记录）

Photon 命中率并非 100%，且失败原因不同，处理方式也不同：

| 现象 | 原因 | 应对 |
|---|---|---|
| 请求报 `SSL: UNEXPECTED_EOF_WHILE_READING` / timeout | 瞬时网络错误（不是查不到） | 脚本已内置 3 次退避重试；偶发仍失败就重跑 |
| 带上下文前缀的查询返回 0 条 | Photon 对「前缀 + 地名」整串召回差（`云南勐腊 勐腊县城` = 0 条，`勐腊县城` = 1 条） | 脚本只用纯地名查询，上下文只用于归属校验 |
| 「城市+景点」整串查不到（`杭州西湖`、`普洱茶马古城`） | 同上，整串不是一个 token | 脚本会拆出景点名（`西湖`/`茶马古城`）重试 |
| 机构前缀查不到（`中科院西双版纳热带植物园`=0 条，`西双版纳热带植物园`=2 条） | 前缀不在索引里 | 脚本自动剥掉「中科院/中国科学院/国家级」等前缀 |
| 命中同名小地物（`望天树` 命中勐仑植物园里的望天树 `natural=tree`） | OSM 里景区没建 POI，只有同名树 | 脚本拒绝「树/小径」类命中；该点需手填坐标 |
| 命中县界标签点（`勐腊县` 第一条 21.6551,101.4786 离县城约 20km） | Photon 混入行政边界形心 | 脚本给行政标签点降权，优先聚落节点（21.4619,101.5650） |
| 命中跨省同名（`小熊猫庄园` → 成都 `小熊猫园`） | 名称相同、省份不同 | 脚本用 region 的省级 token 硬校验（含 ISO 代码如 `ZJ`）后拒绝 |
| OSM 里确实没有这个 POI（望天树景区、普洱太阳河森林公园、普洱茶马古城） | 数据缺失，任何查询都无解 | 手填坐标并写入 `references/poi-coords.json` |

## 三、标准作业顺序

1. **先查缓存**：`references/poi-coords.json`（脚本自动查，键名为站点名，支持子串命中）。
2. **跑 dry-run 看核对表**：
   ```bash
   python3 bin/generate_travel.py <itinerary.json> --geocode-only
   ```
   有坐标缺失或低置信时返回码为 2，**先补坐标再出图**，别先出图再返工。
3. **核对每一行**：脚本会打印「命中的行政层级 + osm 类型 + 距上一站距离」。
   - 出现 ⚠️ 低置信 → 人工核对；
   - 距上一站距离离谱（如几百公里）→ 基本是错位；
   - `[自动编码]` 的点务必与预期地点一致。
4. **手填坐标**（Photon 无解时）：优先找 OSM/Wikipedia（WGS-84 直接填）；只能拿到腾讯/高德/公示坐标时，先 `gcj2wgs` 换算。
5. **回写缓存**：把核过的坐标写进 `references/poi-coords.json`（可用 `--dump-coords` 生成片段），冷门景区坐标长期不变，下次直接命中。
6. **出图后复看核对表**，发现明显错位（标到邻市/邻县）先修正再交付。

## 四、常见坑速查

- 「县城」在地名库里通常落在 `XX镇/XX街道` 节点上，不要用县界形心。
- 「XX站/XX码头」常与景区同名（如 `野象谷[station]` 22.1146 vs `野象谷[zoo]` 22.1698），注意 `osm_value`。
- 一个景点可能同时存在「景区」「索道下站」「停车场」多个 POI，取`景区/attraction/zoo/garden` 一类。
- 手填坐标后仍在图上偏，先怀疑坐标系（GCJ/WGS 混用），而不是地名写错。
