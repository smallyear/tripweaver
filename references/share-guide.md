# 手绘分享图规范

本文件说明「无地图分享图」（Phase 4.5）的产物、插画约定与降级规则。分享图是用户最可能真正发出去的东西，优先级不亚于地图。

## 为什么要有

- 地图 HTML 适合自己看路线，手机上打开体验一般，也不便发群。
- `route_map.png` 是 1600×3028 的竖长图，发到朋友圈缩略后左侧文字行程基本看不清。
- 分享图按手机原生比例排版（1080×1440 等），纯插画 + 手写体 + 大字，缩略也读得清。

## 命令

```bash
python3 bin/generate_share.py <itinerary.json> [--out <目录>] [--types all|day,cover,grid,quote,map,mapday]
```

- `--out` 省略时为 `<itinerary 同目录>/share`；指到任意目录也能正常加载插画（脚本按相对路径引用）。
- `--types` 只接受 `all|day|cover|grid|quote`，写错会直接报错退出，不会静默出 0 张。
- 依赖 `itinerary.json` 与 `<itinerary 同目录>/illustrations/`。
- 渲染复用系统 Chrome（与 `generate_travel.py` 同一链路），无需下载 chromium。
- 以 `device_scale_factor=2` 出高清图。

## 产物

| 文件 | 尺寸（CSS px） | 用途 |
|---|---|---|
| `day_XX.png` | 1080×1440 | 每日海报：DAY 徽章 + 日期 + 当日插画 + 头条站名 + 当日站点时间线 |
| `cover_hero.png` | 1600×1000 | 封面，标题 + 日期区间 + 人数，发群/朋友圈首图 |
| `grid.png` | 1200×1200 | 全部可用插画拼一张速览，列数按数量自适应（1/2/3） |
| `quote_XX.png` | 1080×1350 | 金句卡 ×3，收尾或九宫格补位 |
| `map_poster.png` | 1080×1920+ | **整趟地图海报**：方形地图 + 每日一行摘要，行程总览首图 |
| `map_day_XX.png` | 1080×1350 | **每日地图卡**：当日路线 + 站点时间 + 备注，只显示当天站点/路段 |

每日海报的「头条站」选取顺序：**当天第一张有插画的站** → 第一个非机场站 → 第一站。所以「每日头牌有插画」直接决定海报质量。

## 插画约定（最容易出错的一环）

- 目录：`output/<行程>/illustrations/`；封面固定 `cover.png`。
- 站点插画文件名 = **站名中文真名**，如 `中科院西双版纳热带植物园.png`。HTML 里用 `encodeURIComponent(站名)+".png"` 引用，`file://` 加载时会解码回中文，正好匹配磁盘文件。
- **不要把磁盘文件名写成 `%E9%87%8E…png` 这种百分号编码**：`file://` 会双重解码导致 404，图永远加载不出来（2026-09-29 实际踩过，多张海报只剩占位纸卡）。
- 封面 `cover.png` 同时用于：每日海报缺插画时的兜底、封面 hero 背景、金句卡轮换素材。
- 插画缺失**不算错误**：页面自动降级为「纸卡 + 站名」，`onerror` 隐藏，不阻断渲染。

## 生成插画的成本纪律

- 插画走 ImageGen，**消耗用户自己的积分**（约 5–10 积分/张），生成前必须征得用户同意。
- 只画「每日头牌」：一天一张，7 天行程封顶 7 张 + 1 张封面。机场、县城、酒店、服务区、途经点不画。
- 提示词必须包含 `no text / 无文字`；所有中文由页面排版叠加（AI 写中文不可靠）。
- 用户拒绝或积分不足 → 仍出纯排版版分享图，不要因此跳过 Phase 4.5。

## 地图版（map / mapday）

分享图本身不带底图，地图版另行生成，**生成前先问用户要不要**（见 SOP Phase 4.5）：

- `--types map`：整趟一张 `map_poster.png`。地图标签自动精简——用「最远点采样」挑最多 5 个地理位置铺开的站（跳过机场/县城/超长名），其余隐藏，避免标签全挤在一处；地图高度按路线长宽比自适应（1080×520–1100），宽路线用矮横幅。
- `--types mapday`：每天一张 `map_day_XX.png`。**不做标签精简**；地图只显示当天的站点与路段（`window.__filterDay__` 按天过滤 marker 与折线），单站天自动用 zoom 12。
- `all` 含 `map`、不含 `mapday`：每日卡更耗时（每天多一次地图渲染，7 天约多 1–2 分钟），必须由用户决定。
- **不消耗 ImageGen 积分**：地图是复用 `generate_travel.py` 的 Leaflet 页面做元素截图，不是 AI 生图；但**需要网络**拉瓦片，离线时会提示并跳过地图版，不影响其他分享图。
- 坐标缺失时会先按「缓存 → Photon → Nominatim」补齐（与主流程一致），所以 `itinerary.json` 只写站名也能出图；补齐后仍无坐标则跳过并提示先跑 `generate_travel.py`。
- 中间产物：`_map_source.html`、`_map_*.png`（poster/day 卡引用），交付时不当作成品展示。

## 视觉风格

- 分享图固定走「水彩手账」纸感（米色纸底 + 和纸胶带 + 手写体），与地图页 `watercolor` 主题呼应。
- 手写体使用 macOS 系统字体栈（`HanziPen SC` / `Hannotate SC` / `STKaiti` / 楷体），**不依赖外部 CDN**。
- 金句池在脚本内 `QUOTES`，可按行程调性扩充（自然/亲子/慢游）。
- 每日海报页脚会带 `trip.theme` 的首个标签（如「自然风光」），不会硬编码亲子。

## 交付前自检

脚本内置自检（渲染后测量 DOM），会逐张打印 `✅ / ⚠️ / ❌`：

- **❌ 阻断（退出码 1）**：文字溢出画布（元素超出 `.frame`）、页脚压住站点列表、图片加载失败（文件存在但解码失败）、渲染异常。修复后重跑，不要带着 ❌ 交付。
- **⚠️ 告警（不阻断）**：插画缺失（已用占位纸卡）、`grid` 可用插画不足 2 张（九宫格参考价值低）。这些属于「没有插画也能交」的正常降级，如实告知用户即可。
- `--skip-verify` 只渲染不检查，仅在排查问题时用。

脚本测不出、仍需人眼看的：

1. 打开 `share/day_01.png`：插画风格是否与行程调性相符、没有奇怪的 AI 文字。
2. 超长站名是否已自动缩字号（脚本会拦溢出，但两行折行仍可能不美观）。
3. `cover_hero.png` 的标题与日期区间是否正确（标题由 `trip.title` 直接渲染，不会自动改写）。
4. 交付时给出分发建议：`map_poster` 做行程总览首图，封面发群/朋友圈，`day_XX`/`map_day_XX` 发给当天同行的人，`quote_XX` 做收尾或九宫格。
