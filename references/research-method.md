# 先搜后规划：需求澄清、搜索问题库与信息核验

> 旅游信息的时效性极强：门票价格、开放时间、预约政策、交通班次、限流规则在节假日前后经常变动。
> **任何行程决策都要建立在实时检索结果之上，不凭记忆写价格与政策。**
> 本文件是 Phase 2（访谈）、Phase 2.5（预审）、Phase 5/6（清单/气象）的共用知识库。

---

## 一、需求澄清表（缺项用默认值，不逐条盘问）

| 信息 | 说明 | 缺省处理 |
|---|---|---|
| 目的地 | 城市/景区，或只说类型（海边/山里/古城） | 没定 → 按「季节 + 同行人」给 2–3 个候选 |
| 时间与天数 | 出发/返回日期，或「X 天」 | 必须问清，否则排不出动线 |
| 出发城市 | 用于算首日到达与末日晚宿 | **第一轮就问，要具体城市**（不要给「华东/华南」这种分区选项） |
| 同行人结构 | 带娃（年龄/身高）、带老人（年龄段）、纯成人 | **决定节奏的核心变量**，见下表 |
| 预算 | 总额或人均 | 按目的地常规水平估算，并注明是估算 |
| 交通偏好 | 自驾 / 高铁 / 飞机 | 按距离与目的地推断，写明假设 |
| 节奏偏好 | 紧凑打卡 / 休闲躺平 | 带娃、带老人默认休闲 |
| 必去清单 | 点名要去的点 + 可放弃的弹性项 | 做成多选清单一次问掉，省轮次 |

### 同行人结构 → 节奏参数（Phase 2.5 单日时长账用这张表）

| 同行人 | 单日主景点 | 单日移动上限 | 特殊要求 |
|---|---|---|---|
| 带低龄儿童（≤6 岁） | 1–2 个 | 换乘 ≤2 次、单程 ≤1.5h | 半天一个主景点 + 午休；亲子设施/母婴室优先 |
| 带学龄儿童（7–12 岁） | 2 个 | 换乘 ≤3 次 | 加 1 个「孩子会兴奋」的点（动物园/科技馆/玩水） |
| 带老人 | 2 个 | 换乘 ≤2 次、少爬坡 | 每 2h 一个休息点；关注就近医院；长途车两人轮换驾驶 |
| 纯成人 | 2–3 个 | 换乘 ≤3 次 | 可紧凑，但每天留 1 个弹性档 |
| 自驾 | 3–4 个 | 日里程按山区 40–50km/h、城市 25–35km/h 折算 | 末晚住回枢纽旁，返程日零长途 |

> 单日总时长（路上 + 停留 + 用餐）= 亲子/松弛 ≤9–10h，成人紧凑 ≤11h。超了就拆天。

### 门票优惠预判（预算阶段用）

- 儿童：多数景区按**身高**（1.2m / 1.4m 两档）免票或半价，少数按年龄。
- 老人：常见 60–64 岁半价、65 岁以上免票，各地不同。
- 用户没给年龄/身高 → **按优惠价计并写明假设**，交付时提示「以现场核验为准」。

## 二、六维并行搜索（一次发起多路独立搜索）

每条搜索都要带**当前年月**（如「2026-11」），否则极易搜到过期攻略。

1. **整体攻略**：`{目的地} 旅游攻略 最新 {年月}` —— 主流玩法、必去清单、近期变化
2. **门票与预约**：`{景点} 门票价格 预约 {年月}` —— 是否需提前预约/限流（热门景点节假日必查）
3. **交通**：`{目的地} 交通攻略 {年月}` —— 到达交通、市内交通；自驾查停车/限行/路况
4. **住宿**：`{目的地} 住宿 区域推荐` —— 结合动线选住宿区，而不是选「评分最高」
5. **气候背景**：`{目的地} {月份} 天气 气候特点` —— 雨季/雪季/台风季、防晒防暑
6. **政策与避坑**：`{目的地} 最新政策 避坑 注意事项 {年月}` —— 景区调整、管制、消费陷阱

### 分场景问题库

**城市亲子**
- `{城市} 亲子游 攻略 {月份}`｜`{城市} 适合孩子 博物馆/科技馆/动物园`
- `{景点} 门票 预约 儿童票`｜`{城市} 地铁 亲子 出行`
- `{城市} 暑期 人多吗 避坑`｜`{城市} {月份} 天气 穿衣`

**自然风光自驾**
- `{目的地} 自驾 路况 {年月}`｜`{景区} 开放时间 索道/观光车 票价`
- `{目的地} 停车 限行 自驾注意事项`｜`{目的地} 周边 住宿 离景区近`
- `{目的地} {月份} 天气 穿衣 海拔`｜`{季节特征} 注意事项`

**海岛/海滨**
- `{海岛} 最佳季节 消费`｜`{海岛} 船票/航班 预订`｜`{海岛} 亲子 适合吗`｜`台风 {月份}`

**古镇/人文**
- `{古镇} 门票 开放时间`｜`{古镇} 夜游 灯光 表演`｜`{古镇} 住宿 城内/城外`｜`节假日 人流量 预约`

### L1 顾问快答的最小搜索集

单点问题（门票/开放时间/交通/天气）只跑 **1–2 条**搜索，不要拉六维：

| 问题类型 | 搜索 | 回答必须带 |
|---|---|---|
| 门票/开放时间 | `{景点} 门票 开放时间 {年月}` | 价格、优惠、预约要求、来源与月份 |
| 交通/车次 | `{出发}→{到达} 高铁/航班 {月份}` | 时长、班次区间、票价区间 |
| 天气 | 直接跑 `bin/generate_weather.py` 或问预报 | 温度区间、降水、对出行的影响 |
| 政策/限流 | `{景区} 限流 预约 公告 {年月}` | 是否需要预约、放票时间 |

回答控制在 **3 条以内**，末尾一句「需要我按这个排进行程吗？」——把 L1 当钩子，不当终点。

## 三、天气查询（两个时点，缺一不可）

**时点一：规划期气候研判**（Phase 5 用）
查该季节气温区间、降水概率、是否台风/暴雨季 → 决定室内外配比与穿衣建议。写进 `plan.html` 的「天气研判」。

**时点二：出发前实时复核**（Phase 6，可二次触发）
行程进入 16 天预报窗口后跑 `bin/generate_weather.py`，逐日输出：日期 / 天气 / 温度区间 / 降水 / **对当日行程的影响**。
天气影响由专家写进 `itinerary.json` 的 `day_impacts`（见 `references/plan-doc-guide.md`），如「D2 有雨 → 上午改室内备选（傣族园→民族博物馆）」。

实时与规划期冲突时**以实时为准**，并主动调换当天顺序，而不是只说一句「注意天气」。

## 四、信息核验清单（关键信息必须溯源）

| 信息类型 | 核验来源 | 为什么 |
|---|---|---|
| 门票价格 / 开放时间 | 景区官网、官方公众号、订票平台当日页 | 节假日调价、季节性闭园频繁 |
| 预约 / 限流 | 官方预约平台、景区公告 | 没预约可能白跑 |
| 交通班次 | 12306、航司、客运官网 | 班次随季节调整 |
| 天气 | 权威天气源（出发前 3 天再复核） | 决定备选方案 |
| 特殊政策 | 政府/景区公告、权威新闻 | 管制、关闭、封路 |

### 标注格式

- 单条：（据景区官网 2026-11 信息）
- 多来源冲突：**取官方价并注明区间**，如「门票 ¥120（官网）/ ¥99（OTA 促销），预算按官网价计」。
- 无法核验：明写「出发前复核」，不要省略。

### 三条硬纪律

1. 价格、开放时间、预约政策：**必须检索，不凭记忆**。
2. 每条关键信息带**来源 + 信息月份**。
3. 冲突取官方，并提示「以官方当日为准」。

## 五、边界

不代订机票/酒店/门票、不办签证、不买保险。需要用户自己动手的，写进 Checklist 的预约时间线，而不是替他操作。
